论文可视化项目双机部署流程与命令文档
==================================

一、部署目标
------------
采用双机部署：

1. app-server（公网）
   - 前端静态页面
   - Nginx
   - server1

2. crypto-server（内网/白名单）
   - server2

当前实际部署关系：
- app-server 内网 IP：172.16.0.11
- crypto-server 内网 IP：172.16.0.8

注意：
- app-server 通过内网地址访问 crypto-server
- SERVER2_URL 固定写为：http://172.16.0.8:5002

--------------------------------------------------

二、服务器购买建议
------------------
两台机器都建议：
- Ubuntu Server 22.04 LTS 64位
- 2核4G
- 系统盘 50GiB
- 同地域
- 同可用区
- 同 VPC
- 同子网

建议：
- app-server 开公网 IP
- crypto-server 也可开公网 IP，方便维护
- 两台机器间业务通信走内网 IP

--------------------------------------------------

三、安全组建议
--------------
1. app-server 安全组建议开放：
- TCP 22
- TCP 80
- TCP 443
- 放通内网
- ICMP 可选
- 不需要 TCP 3389

2. crypto-server 安全组建议开放：
- TCP 22
- TCP 5002（最好限制来源为 app-server 内网 IP）
- 放通内网
- ICMP 可选
- 不需要 TCP 80
- 不需要 TCP 443
- 不需要 TCP 3389

九、修正 Flask debug 模式，避免 systemd 托管失败
------------------------------------------------
原因：
原始 app.py 使用了 debug=True，配合 Flask reloader 在 systemd 下容易出问题。

需要改成：
- debug=False
- use_reloader=False

1. 修改 crypto-server 的 server2/app.py
cd ~/paper-visualization/backend/server2
cp app.py app.py.bak

把原来的：
app.run(host="0.0.0.0", port=5002, debug=True)

改成：
app.run(host="0.0.0.0", port=5002, debug=False, use_reloader=False)

可用脚本替换：
python3 - <<'PY'
from pathlib import Path
p = Path("app.py")
s = p.read_text()
old = 'app.run(host="0.0.0.0", port=5002, debug=True)'
new = 'app.run(host="0.0.0.0", port=5002, debug=False, use_reloader=False)'
if old not in s:
    raise SystemExit("未找到目标文本")
p.write_text(s.replace(old, new))
print("patched server2/app.py")
PY

2. 修改 app-server 的 server1/app.py
cd ~/paper-visualization/backend/server1
cp app.py app.py.bak

把原来的：
app.run(host="0.0.0.0", port=5001, debug=True)

改成：
app.run(host="0.0.0.0", port=5001, debug=False, use_reloader=False)

可用脚本替换：
python3 - <<'PY'
from pathlib import Path
p = Path("app.py")
s = p.read_text()
old = 'app.run(host="0.0.0.0", port=5001, debug=True)'
new = 'app.run(host="0.0.0.0", port=5001, debug=False, use_reloader=False)'
if old not in s:
    raise SystemExit("未找到目标文本")
p.write_text(s.replace(old, new))
print("patched server1/app.py")
PY

十、配置 systemd 开机自启
------------------------
A. crypto-server：server2
创建文件：
sudo nano /etc/systemd/system/paper-server2.service

内容如下：
[Unit]
Description=paper visualization server2
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/home/ubuntu/paper-visualization/backend
Environment=PYTHONUNBUFFERED=1
ExecStart=/home/ubuntu/paper-visualization/backend/.venv/bin/python -m server2.app
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target

启用：
sudo systemctl daemon-reload
sudo systemctl enable paper-server2
sudo systemctl start paper-server2

检查：
sudo systemctl status paper-server2 --no-pager
ss -ltnp | grep 5002
curl http://127.0.0.1:5002/api/v1/crypto/health

B. app-server：server1
创建文件：
sudo nano /etc/systemd/system/paper-server1.service

内容如下：
[Unit]
Description=paper visualization server1
After=network.target

[Service]
User=ubuntu
WorkingDirectory=/home/ubuntu/paper-visualization/backend
Environment=PYTHONUNBUFFERED=1
Environment=SERVER2_URL=http://172.16.0.8:5002
ExecStart=/home/ubuntu/paper-visualization/backend/.venv/bin/python -m server1.app
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target

启用：
sudo systemctl daemon-reload
sudo systemctl enable paper-server1
sudo systemctl start paper-server1

检查：
sudo systemctl status paper-server1 --no-pager
ss -ltnp | grep 5001
curl http://127.0.0.1:5001/api/v1/health

C. 如果 systemd 启动失败，但 curl 端口又是通的
通常是之前手工运行的 Flask 进程还占着端口。

可先清理旧进程：
sudo systemctl stop paper-server1
pkill -f 'server1.app'
sudo systemctl reset-failed paper-server1
sudo systemctl start paper-server1

sudo systemctl stop paper-server2
pkill -f 'server2.app'
sudo systemctl reset-failed paper-server2
sudo systemctl start paper-server2

十二、安装并配置 Nginx（只在 app-server 执行）
----------------------------------------------
1. 安装 Nginx
sudo apt install -y nginx
sudo systemctl enable nginx
sudo systemctl start nginx
sudo systemctl status nginx --no-pager

2. 拷贝前端静态文件
sudo mkdir -p /var/www/paper-visualization
sudo cp -r ~/paper-visualization/dist/* /var/www/paper-visualization/
ls /var/www/paper-visualization

3. 配置站点
sudo nano /etc/nginx/sites-available/paper-visualization

写入：
server {
    listen 80;
    server_name _;

    root /var/www/paper-visualization;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:5001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

4. 启用配置
sudo rm -f /etc/nginx/sites-enabled/default
sudo ln -sf /etc/nginx/sites-available/paper-visualization /etc/nginx/sites-enabled/paper-visualization
sudo nginx -t
sudo systemctl restart nginx

5. 本机测试
curl http://127.0.0.1
curl http://127.0.0.1/api/v1/health

预期：
- 第一个返回前端 HTML
- 第二个返回 server1 的健康检查 JSON

十五、常见问题
--------------
1. curl 127.0.0.1:5001/5002 连接被拒绝
原因：
- 对应服务没启动
- systemd 启动失败
- 端口被旧进程占用

排查：
ss -ltnp | grep 5001
ss -ltnp | grep 5002
journalctl -u paper-server1 -n 50 --no-pager
journalctl -u paper-server2 -n 50 --no-pager

2. systemd 显示 active，但 curl 不通
常见原因：
- Flask debug/reloader 导致 systemd 进程模型异常
解决：
- 改 app.run 的 debug=False, use_reloader=False

3. 启动失败提示 Address already in use
原因：
- 手工运行的 python -m server1.app / server2.app 还在
解决：
pkill -f 'server1.app'
pkill -f 'server2.app'

4. 服务器重启后公网 IP 变化
影响：
- SSH 登录地址变化
- 浏览器访问地址变化

一般不影响：
- 双机内网互调
因为 server1 指向的是内网地址 172.16.0.8:5002

如果希望公网 IP 固定：
- 给实例绑定 EIP（弹性公网 IP）

十六、当前部署口径总结
----------------------
本项目采用双机部署架构：

1. app-server
   - 部署前端静态页面
   - 部署 Nginx
   - 部署协调服务 server1
   - 对外提供统一访问入口

2. crypto-server
   - 部署密码学服务 server2
   - 仅通过内网提供服务

3. 服务关系
   - 浏览器 -> app-server:80 -> Nginx
   - Nginx -> server1:5001
   - server1 -> crypto-server:5002（内网）

4. 服务托管
   - server1：systemd
   - server2：systemd
   - nginx：systemd

至此，双机后端、前端静态页面、Nginx 反向代理、开机自启全部完成。

每次开机后，可使用以下命令检查服务状态：
# crypto-server
sudo systemctl is-active paper-server2
curl -s http://127.0.0.1:5002/api/v1/crypto/health

# app-server
sudo systemctl is-active paper-server1 nginx
curl -s http://127.0.0.1/api/v1/health

十七、每次改动后的更新命令（固定流程）
--------------------------------------
说明：每次代码改动后，按“改动类型”执行对应命令，不需要每次全量重装。

A. 只改前端（`src/`、`index.html`、`vite` 配置）
在 app-server 执行：
cd ~/paper-visualization
git pull
npm ci
npm run build
sudo mkdir -p /var/www/paper-visualization
sudo cp -r ~/paper-visualization/dist/* /var/www/paper-visualization/
sudo systemctl restart nginx
curl -s http://127.0.0.1/api/v1/health

B. 改了 server1（`backend/server1` 或 `backend/shared_contract`）
在 app-server 执行：
cd ~/paper-visualization
git pull
cd backend
source .venv/bin/activate
pip install -r requirements.txt
sudo systemctl restart paper-server1
sudo systemctl status paper-server1 --no-pager
curl -s http://127.0.0.1:5001/api/v1/health
curl -s http://127.0.0.1/api/v1/health

C. 改了 server2（`backend/server2` 或 `backend/shared_contract`）
在 crypto-server 执行：
cd ~/paper-visualization
git pull
cd backend
source .venv/bin/activate
pip install -r requirements.txt
sudo systemctl restart paper-server2
sudo systemctl status paper-server2 --no-pager
curl -s http://127.0.0.1:5002/api/v1/crypto/health

D. 同时改了前端 + server1 + server2（当前最常见）
执行顺序：
1) 先在 crypto-server 执行 C
2) 再在 app-server 执行 B
3) 最后在 app-server 执行 A
4) 联动回归测试：
curl -X POST http://127.0.0.1:5001/api/v1/tasks \
  -H "Content-Type: application/json" \
  -d '{}'

E. 只有依赖文件变更时，才必须额外关注
1) 如果改了 `package.json` / `package-lock.json`：
cd ~/paper-visualization
npm ci

2) 如果改了 `backend/requirements.txt`：
cd ~/paper-visualization/backend
source .venv/bin/activate
pip install -r requirements.txt

F. 如果改了 systemd 服务文件（`/etc/systemd/system/*.service`）
sudo systemctl daemon-reload
sudo systemctl restart paper-server1
sudo systemctl restart paper-server2
sudo systemctl restart nginx
